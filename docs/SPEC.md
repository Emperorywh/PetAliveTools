## 1. 产品愿景与核心命题

把用户自己的真实宠物转化为 Windows 桌面常驻伴侣，追求三个目标：

1. **高身份一致性**——它就是"那只"，不是"一只像它的"。
2. **自然动作连续性**——动作之间无缝衔接，看不出"视频拼接"。
3. **基础生命感**——它像在过自己的生活，而非循环播放的 GIF。

### 1.1 路线选择的根本权衡

用户否决了所有建模路线（3D / 2D 绑定 / 扩散逐帧），理由是"任何建模都还原不了我自己的真实宠物"。由此采用**视频精灵（Video Sprite）路线**：拍真实视频 → 抠出透明前景 → 状态机按需播放/衔接 → 叠在桌面。

该路线天然保住全部身份维度（视频同时含外观/动作/声音/气质），但引入三个固有难题，本规格的核心工程量都围绕它们：

- **D1 毛发抠像**：纯色背景色键可解，但需规范采集（§4、§5）。
- **D2 离散片段 vs 连续性**：用锚定姿态中转机制（§8）。
- **D3 视频无法程序化叠加微动作**：无法像 3D 那样在固定画面上加呼吸/眨眼层，故"生命感"只能靠素材多样性 + 调度随机性近似（§9.5）。

## 3. 技术栈

**决策：Electron（Web 技术）**

### 3.1 选型理由
- 透明带 Alpha 通道视频播放是本项目的第一约束。Electron（Chromium）的 `<video>` 原生支持 **WebM（VP8/VP9 带 alpha）**，是所有候选方案里透明视频最现成的路径。
- Web 生态成熟，FSM/调度/UI 用 TS 开发效率高。
- 跨窗口、托盘、全局快捷键、自启均有成熟 API。

### 3.2 已知代价与缓解
| 代价 | 缓解 |
|---|---|
| 常驻内存偏重（基线 ~150–250MB，含 GPU/渲染进程） | 单窗口、禁用多余模块；仅一个隐藏 BrowserWindow + 一个透明宠物窗口；空闲时降低调度频率。 |
| 电池 / CPU | 仅解码当前播放的单段循环；**VP9-alpha 无硬解可用，走软解**——靠归一化小尺寸片段 + 30fps 控制开销（§14）；空闲态拉长调度间隔。 |
| 包体大 | 用 electron-builder，必要时仅打包 win-x64。 |

### 3.3 关键依赖（提案）
- 视频：`<video>` + WebM(VP9-alpha)；解码/拼接用 `ffmpeg`（打包二进制，离线）做入库转码。
- 透明窗口：`BrowserWindow { transparent:true, frame:false, alwaysOnTop:true, setIgnoreMouseEvents }`。
- 全局快捷键：`globalShortcut`（隐藏安全阀）。
- 自启：`auto-launch`。

## 4. 素材采集规范（拍摄清单）

> 视频路线"垃圾进垃圾出"。本节是质量的源头，也是用户的拍摄手册。**提案**：内置一份可勾选的拍摄清单（与 §5.5 导入 UI 同源）。

### 4.1 硬性拍摄规范
- **背景**：单一均匀纯色（推荐中灰/中蓝布幕；避免与宠物毛色相近）。背景需静态、无阴影、无杂物。绿幕可选但非必须（纯色色键足够）。
- **光照**：均匀漫射，避免硬阴影落在背景上（阴影会破坏色键）。正面/侧面补光，宠物身上无过曝。
- **机位**：固定三脚架；**水平侧机位**（宠物侧面朝向镜头，便于"在桌面上行走"的阅读感）；机位距离全程一致（保证尺度统一）。
- **地面**：拍摄台面即为"地面"，所有片段同一地面线高度。
- **参数**：1080p 及以上，30–60fps，每段时长 3–10 秒（行走类 5–8 秒便于覆盖屏幕宽度）。
- **环境声**：拍摄时保持安静，关闭风扇/空调/电视（音频规范见 §4.8）。

### 4.2 锚定姿态纪律（连续性的基础）

- **锚定集合（v0.2 修订）**：采用**双锚定**——
  - `端坐`（**主锚定**）：正面、放松、面向镜头。大多数状态的中转枢纽。
  - `站立`（**副锚定**）：侧面、四肢着地静止。行走/转身类的起止枢纽。
  全文仅此两个枢纽姿态。
- **起止模板**：每段非循环动作必须 `[锚定] → [动作] → [锚定]` 起止；状态切换经锚定中转（§8）。各类片段的标准起止：

| 片段类别 | 起始锚定 | 结束锚定 |
|---|---|---|
| 端坐变体 / 理毛 / 睡眠 / 趴卧（经趴下过渡进入） | 端坐 | 端坐 |
| 行走 / 转身 | 站立 | 站立 |
| 互动响应（抚摸 / 点击 / 呼唤 / 拖拽） | 端坐 | 端坐 |
| 过渡片段（坐↔站、坐↔趴卧） | 一端锚定 | 另一端锚定 |

- **循环类片段**（如理毛、睡眠呼吸）需标注无缝 loop 入/出点（§5.3），进出循环须经独立过渡片段。

### 4.3 方向与不对称花纹（关键！）
- 沿底部条带行走需要**左行、右行**两个方向。
- **决策性提案**：对**花纹不对称**的宠物（如身上一块斑、折耳单侧、断尾），**禁止用镜像翻转生成反方向**——必须**实拍两个方向**。镜像会让不对称特征翻边，破坏身份一致性。
- 对称宠物可只拍一个方向、运行时镜像（节省一半采集量）。**对称性为宠物级属性**，记录在 persona.json（§12.1），片段元数据不重复存储（§5.4）。

### 4.4 完整拍摄清单（按四大行为类别）

> 必拍=最小可用集；选拍=丰富生命感；个性=你宠物独有。每项尽量 2–3 个变体以反循环（§9.5）。
> ★ = **最小启动集**（§4.6）：凑齐即可得到一只连贯可用的宠物。

**A. 基础生命状态（必拍，构成 FSM 骨架）**
| 动作 | 必/选 | 方向 | 说明 |
|---|---|---|---|
| ★ 端坐（主锚定） | 必拍 | 正面 | 大多数中转的基准姿态 |
| ★ 站立（副锚定） | 必拍 | 侧面 | 行走/转身的起止枢纽 |
| ★ 行走 | 必拍 | 左+右 | 5–8 秒，覆盖屏幕宽度；起止于站立；入库需跟踪裁切（§5.3） |
| ★ 趴卧 | 必拍 | — | 静止/呼吸 loop |
| ★ 睡眠 | 必拍 | — | 长循环，含翻身变体 |
| 理毛 | 选拍 | — | loop |
| 转身 | 必拍 | 双向 | 边缘转向用；起止于站立 |
| ★ 起身/趴下过渡 | 必拍 | — | 坐↔站、坐↔趴卧，锚定间过渡 |

**B. 互动响应（选拍，增强连接）**
- 被抚摸享受（眯眼/呼噜/蹭手）｜抬头看镜头（点击呼应）｜被呼唤转身｜被抱起/悬空（拖拽反应）｜松手落回地面
- **拍摄此类片段必须遵守 §4.7 人体遮挡规范**（背景色袖套 / 场外引导），画面中只保留宠物反应。

**C. 个性招牌动作（个性，身份灵魂）**
- 由用户自定义捕捉：翻肚皮 / 叼玩具 / 打呼噜 / 特定怪睡姿 / 蹭人 / 冲刺跑酷……每项打上 `signature` 标签，低频偶发触发。
- 含道具的招牌动作（叼玩具等）同时遵守 §4.7 道具规则。

**D. 情绪/需求表达（选拍，养成感）**
- 讨食 / 喝水 / 求玩 / 无聊 / 开心 / 烦躁
- 进食/喝水等含食盆道具的片段按 §4.7 道具规则处理，过渡走 §8.4。

### 4.5 反循环素材（§9.5 配套）
- 每个**高频闲置状态**拍 **2–3 个变体**（如 3 种不同坐姿/睡姿）。
- 拍一组**稀有动作**：哈欠 / 伸懒腰 / 挠痒 / 抖耳 / 吐舌，低概率偶发插入。

### 4.6 采集策略：抓拍优先，后期定起止（v0.2 新增，提案）

动物不会按指令完成"锚定→动作→锚定"。**不要试图引导表演**：
- 以长时段固定机位**抓拍**（每次 10–20 分钟），后期从素材中**截取天然满足起止模板的片段**（如行走前后宠物自然停驻站立的瞬间）。
- 单次拍摄以 1–2 类动作为目标，降低宠物与用户的疲劳；按 §5.5 清单进度分批补拍。
- **最小启动集**：端坐、站立、行走×2（左/右）、趴卧、睡眠 **6 段主体** + 坐↔站、坐↔趴卧过渡段（过渡可从同批长素材截取）。先凑齐启动集即可运行，其余按清单迭代补拍。

### 4.7 人体遮挡与道具规范（v0.2 新增，关键！）

色键只去除背景色，**人手、手臂、食盆、玩具等非背景物体都会保留在成片里**。

- **人体遮挡**：拍摄抚摸/抱起等互动片段时，操作者须穿**背景色长袖/手套**（与背景幕同色系），使入镜肢体被一并键除，画面只保留宠物的反应（眯眼、蹭、悬空挣扎）。无法穿袖套的场景改为**场外引导**（如用零食从镜头方向引导抬头，代替"点击呼应"中的手指）。
- **道具类片段**（进食/喝水/叼玩具）：道具会出现在画面中，导致片段首尾帧与锚定姿态不一致，**不能走锚定中转**。此类片段打 `prop: true` 标签（§5.4），过渡统一用 §8.4 的短淡入淡出；道具在片段全程保持静止。
- 被抱起/悬空片段若实在无法避免手部可见，允许该片段例外保留手部（拖拽时用户注意力在光标，容忍度较高），但须在导入预览中确认观感可接受。

### 4.8 音频采集规范（v0.2 新增）

声音是身份四维之一（§0），叫声/呼噜/进食声都依赖采集质量：
- 拍摄环境保持安静：关闭风扇/空调/电视，远离街道噪声源。
- 机顶或领口麦克风距宠物 1–2m；每段视频**保留原始音轨**入库，运行时默认分离使用（§11.1）。
- **音画同步例外**：宠物在片段中实际发声的（叫唤/哈欠声/进食声），该片段标记 `embeddedAudio: true`（§5.4），播放时保留内嵌音轨保证同步，不另叠加采样。

## 5. 抠像与入库管线

### 5.1 色键抠像
- **算法（提案）**：HSV/YCbCr 色键，取背景参考色 → 容差阈值 → 生成 alpha 蒙版。
- **边缘处理**：色溢出抑制（去边缘背景色污染）、alpha 蒙版轻微收缩+羽化（消除毛边杂色）。
- **毛发**：纯色背景下色键对硬边缘可靠；半透明绒毛会有损失——**这是质量悬崖**，入库 UI 提供**抠像预览 + 边缘放大检查**，质量差则引导重拍（调背景色/补光）。
- **背景参考帧**：要求用户先拍 1–2 秒空背景作为参考帧（支持背景减除辅助，提升边缘稳定性）。

### 5.2 转码
- 输出 **WebM（VP9 + alpha）**，统一帧率（30fps）、统一分辨率（按宠物身高归一化，§7.4）。
- 比特率平衡体积与质量；长片段（睡眠）可降码率。
- 工具：打包 `ffmpeg`（离线），入库时一次性转码。

### 5.3 片段裁剪、行走跟踪裁切与 loop 标注（v0.2 修订）
- 裁掉首尾准备动作，保留 `[锚定]→[动作]→[锚定]`（非循环）或精确 loop 段（循环）。
- 循环片段标注 `loopInSec`/`loopOutSec`（**统一为秒，浮点**），确保无缝。
- **行走片段跟踪裁切（稳定化）**：抠像后逐帧追踪宠物质心，x 方向跟踪裁切为**定宽片段**（宠物在画面内近似居中），y 方向**锁定地面线**（足部纵坐标全程一致）。跟踪自动生成**逐帧位移曲线**，存为 `<clip_id>.track.json`，导入 UI 支持手动校正关键点（停顿/变速处）。
- 行走片段另需标注行走子段 `moveStartSec`/`moveEndSec`——起止的站定段不参与平移（§7.2）。

### 5.4 打标 schema（片段元数据，v0.2 修订）
```jsonc
{
  "id": "walk_right_01",
  "state": "walk",            // FSM 状态键
  "category": "basic",        // basic|interactive|signature|emotion
  "direction": "right",       // left|right|none
  "anchor": "stand",          // 起止锚定：sit|stand|none(纯循环段)
  "loop": false,              // 是否循环片段
  "loopInSec": null, "loopOutSec": null,  // 循环入/出点（秒，浮点）
  "signature": false,         // 个性招牌（低频触发）
  "variant": 1,               // 同状态变体编号（从 1 起）
  "prop": false,              // 道具类片段（§4.7），过渡走 §8.4
  "embeddedAudio": false,     // 保留内嵌音轨的发声片段（§4.8）
  "audio": "meow_02",         // 关联音频素材 id（可空；embeddedAudio 时忽略）
  "scaleHint": 1.0,           // 尺度归一化用（§7.4）
  "hitbox": [0.1, 0.05, 0.8, 0.9],  // 命中盒 [x,y,w,h]，相对精灵归一化坐标（§6.1）
  // —— 以下仅行走类片段（§5.3、§7.2）——
  "moveStartSec": 0.6,        // 行走子段起点（此前为站定）
  "moveEndSec": 6.2,          // 行走子段终点（此后为站定）
  "track": "walk_right_01.track.json"  // 逐帧位移曲线文件
}
```
> 对称性是**宠物级**属性，记录在 persona.json（§12.1），不在片段元数据中重复。

### 5.5 清单引导式导入 UI
- 导入向导按 §4.4 清单分组展示，每项状态显示**已入库变体数 / 建议数**；**最小启动集（§4.6）置顶**，凑齐即解锁基础运行。
- **缺素材兜底（决策：占位+采集提醒）**：缺失的关键状态在清单中标红，运行时用通用占位片段（端坐）临时顶替，并在托盘/面板提示"还差哪些动作"。
- 每段导入流程：选视频 → 圈选背景参考色/帧 → 抠像预览（边缘放大检查）→ 裁剪/标 loop（**行走类：自动跟踪裁切 + 位移曲线手动校正**）→ 填标签 → 转码入库。

## 6. 渲染层

### 6.1 透明置顶窗口
- 主宠物窗口：`transparent:true, frame:false, alwaysOnTop:true, resizable:false, skipTaskbar:true`。
- **可穿透点击**：默认 `setIgnoreMouseEvents(true, {forward:true})` 让点击落到桌面；当光标进入宠物身体命中盒时切换为可交互（`false`）。
- 命中盒：由片段元数据的 `hitbox` 字段定义（§5.4，入库时标注或按精灵尺寸估算后人工微调）。
- **命中盒缓冲带（v0.2 新增）**：命中盒外扩 8–12px 作为"提前激活区"——光标进入缓冲带即切换为可交互态，缓解穿透切换的抖动与漏触发（实现风险见 §16）。
- **窗口尺寸策略（v0.2 新增）**：窗口尺寸**固定** = 全部片段归一化后的最大包络 + 安全边距，运行中**不随片段 resize**（避免逐段 resize 造成的闪烁/抖动）；各片段按锚定姿态对齐后在窗口内定位（§6.2）。

### 6.2 精灵合成
- `<video>` 元素播放当前 WebM-alpha 片段；通过 CSS `transform: translate(x,y) scale(s) scaleX(±1)` 控制屏幕位置/尺度/方向（镜像仅对对称宠物）。
- **锚点对齐（v0.2 新增）**：所有片段按锚定姿态的关键点（如端坐时的臀部着地点、站立时的足部中心）对齐到窗口内的统一基准坐标，保证锚定中转时无位置跳动。
- 多层叠加：宠物层 + 可选的极轻微全局呼吸缩放（§9.5）+ 可选接触阴影（§6.5）。

### 6.3 全局呼吸缩放近似
- 对整个精灵施加极小幅（如 ±0.6%）、低频（~0.25Hz）的 scale 振荡，近似呼吸节奏。
- **局限**：只是整体缩放，宠物画面本身不会真实胸腹起伏；仅供近距离"不循环感"，不可夸大。

### 6.4 多显示器 / DPI / 分辨率
- 默认主显示器；设置项可选显示器。
- 地面线随工作区/显示器高度自适应（§7）。
- 高 DPI 下 WebM 按归一化尺度渲染，保证清晰。

### 6.5 接触阴影（v0.2 新增，提案，可选）
- 纯渲染层在宠物足部下方投影**极淡的椭圆软阴影**（随 scale 联动、随行走位移跟随），增强"贴地感"。
- 不依赖素材、可在设置中关闭；默认淡到几乎不可察觉，仅用于消除抠像精灵的漂浮感。

## 7. 空间与运动层（底部地面条带）

### 7.1 地面线（v0.2 修订）
- 地面线 = **工作区（workArea）底边**——自动兼容任务栏在任意边、任务栏自动隐藏、多显示器布局（Electron `screen` 模块直接提供）。宠物足部始终贴合地面线。
- 任务栏位置/显示器热插拔/分辨率变化时重新计算（§13）。
- 宠物在地面线上方区域活动（高度不超过屏幕 ~40%）。

### 7.2 行走映射（v0.2 修订：位移曲线驱动）
- 行走片段入库时已完成**跟踪裁切**：宠物在片段内近似居中、足部锁定地面线（§5.3）。**屏幕位移完全由窗口平移提供**，片段内不再有相对位移。
- 运行时：`window.x = startX + displacement(t) × scale`，其中 `displacement(t)` 为该片段的逐帧位移曲线（`*.track.json`）。曲线值随播放速率同步缩放——即使动物变速（停顿/加速），窗口平移也与画面内步态严格同步，**脚爪不滑步**。
- 平移仅作用于行走子段 `[moveStartSec, moveEndSec]`；起止站定段窗口保持静止。
- 屏幕跨度标定：位移曲线末值 × `scaleHint` 即该片段的屏幕位移量；调度层据此安排行走的起止位置与时长（§9）。

### 7.3 方向与边缘转身
- 携带 `direction` 标签选择左行/右行片段；对称宠物可镜像。
- **边缘转身**：到达屏幕左右边界时 → 播放"转身"片段（起止于站立锚定）→ 改变朝向继续行走。
- 不对称宠物必须已拍转身片段；缺失则停在边界等下次调度（兜底）。

### 7.4 尺度归一化
- 所有片段入库时把宠物**肩高**归一化到统一屏幕占比（如屏幕高度的 12–18%，可设置）。
- `scaleHint` 记录该片段相对基准的缩放系数，渲染时统一应用。

### 7.5 拖拽
- 拖拽时进入"悬空/被抱"状态片段（若有）；缺失则保持当前帧 + 跟随光标。
- 松手：若有"落回"片段则播放，随后回到地面线、恢复 FSM。

## 8. 动作连续性：锚定姿态中转机制（核心）

### 8.1 原理（v0.2 修订：双锚定）
所有非循环片段以**锚定集合中的姿态**（端坐/站立，§4.2）起止。状态切换不直接 A→B，而是：
```
当前片段 → [收尾到锚定] → 锚定(可短暂停留) → [目标片段从锚定起始] → 目标动作
```
因为起止姿态一致，视觉上等价于"宠物回到基准姿态再开始下一个动作"，掩盖了片段切换。

- **同锚定切换**（如端坐→理毛）：直接经该锚定中转。
- **跨锚定切换**（如端坐→行走）：先播放过渡片段换锚定，再进入目标：`端坐 → [起身过渡] → 站立 → [行走]`。过渡片段本身起止于两端锚定（§4.2）。

### 8.2 循环片段的处理
- 循环片段（理毛/睡眠/趴卧）自身无缝 loop，进入/退出时经锚定中转：`锚定 → 进入过渡(起身/趴下) → 循环 → 退出过渡 → 锚定`。
- 入库时循环片段需配套"进入/退出过渡"片段（见 §4.4 过渡项）。

### 8.3 兜底过渡
- 若锚定中转仍显微硬（快速交互时），在切换点加 60–120ms 极短淡入/位置缓动作为最后兜底（不依赖额外素材）。

### 8.4 道具类片段过渡（v0.2 新增）
`prop: true` 片段（进食/喝水/叼玩具，§4.7）首尾帧含道具、与锚定姿态不一致，**不走锚定中转**：
- 进入：锚定态 → 150–250ms 淡入至道具片段首帧；退出：同样淡出回锚定。淡化期间窗口位置保持不动。
- 道具片段播放完毕后必须先回锚定，再调度下一动作。
- 淡入淡出时长可在设置中微调；若实测观感仍差，备选方案是补拍"道具进/出场"过渡片段（操作者穿背景色袖套布置/收走道具，§4.7）。

## 9. 行为引擎（确定性状态机）

### 9.1 状态集合（四大类展开）
- **基础生命**：`idle_sit`(主锚定) / `stand`(副锚定) / `walk` / `lie` / `sleep` / `groom` / `turn`
- **互动响应**：`petted`(被抚摸) / `clicked`(点击呼应) / `called`(呼唤) / `dragged`(拖拽)
- **个性招牌**：`signature_*`（用户定义，低频偶发）
- **情绪/需求**：`beg_food` / `drink` / `want_play` / `bored` / `happy`

### 9.2 状态机主干（文字）
```
                  ┌──────────────────────────────┐
                  ▼                              │
[sleep] ⇄ [lie] ⇄ [idle_sit(主锚定)] ⇄ [stand(副锚定)] → [walk] → 边缘 → [turn] → [walk]…
                  │    ↑      │
                  │    └──────┘ (经锚定中转进入各类；跨锚定先经过渡片段)
                  ▼
            [groom]/[signature_*]/[emotion_*]  (按概率/需求偶发，结束后回锚定)

交互触发（抢占）：
  抚摸→[petted]  点击→[clicked]  呼唤→[called]  拖拽→[dragged]
  （结束后回锚定，恢复 FSM）
```

### 9.3 转移驱动
- **概率转移**：每个状态有一组带权出边（权重由性格 §9.6 调制）。
- **需求驱动**：饥饿/疲劳等数值越高，对应状态（讨食/睡眠）权重越大。
- **节律**：昼夜时段调制（夜间睡眠权重高）。
- **交互抢占**：用户交互立即抢占当前状态。
- **调度微随机化**（§9.5）：在权重采样上叠加随机扰动。

### 9.4 需求模型（提案）
| 需求 | 范围 | 变化 | 高位触发 |
|---|---|---|---|
| 饥饿 | 0–100 | 按真实时间缓慢上升（有上限，离线不惩罚到极端） | 讨食 |
| 疲劳 | 0–100 | 活动累积 / 夜间上升 | 睡眠 |
| 愉悦 | 0–100 | 交互（抚摸/玩耍）提升，闲置缓慢回落 | 开心/无聊 |
| 注意力 | 0–100 | 长时间无交互下降 | 求玩/呼唤 |

- **离线处理（提案）**：需求按真实时间推进但有上下限保护；重启不出现"宠物濒死"的惩罚性状态，避免情感压力。

### 9.5 调度微随机化（反循环感，四策并用）
1. **多变体**：同状态多片段随机抽取。
2. **稀有动作**：低概率（如 3–8%）插入 signature/哈欠/伸懒腰。
3. **全局呼吸缩放**：§6.3。
4. **微随机**：播放速率 ±5%（行走位移曲线随速率同步缩放，不会引入滑步，§7.2）、静止时长抖动、出现位置 x 抖动、片段顺序打乱。
- **变体耗尽兜底**：长时间闲置变体用尽时，回退最常见变体并拉长切换间隔，避免明显重复。

### 9.6 性格参数化（提案）
引导式问卷采集 **5 维气质**（0–1）：`活泼 / 慵懒 / 粘人 / 胆小 / 好奇`，映射为：
- 转移权重调制：活泼↑→walk/play 权重↑、idle 权重↓；慵懒↑→sleep/lie 权重↑。
- 需求衰减速率：活泼↑→疲劳↑快、愉悦回落快。
- 交互反应：粘人↑→被抚摸愉悦增益↑、注意力下降更快；胆小↑→交互抢占结束后更快回到 idle/lie 等静止状态、被抚摸权重↓。
- signature 触发频率：好奇↑→稀有动作概率↑。

## 10. 交互层

| 交互 | 触发 | 行为 |
|---|---|---|
| 鼠标抚摸 | 光标进入身体命中盒并移动 | 抢占→`petted` 享受片段 + 愉悦↑ + 偶发呼噜声 |
| 点击/双击 | 点击身体 | 抢占→`clicked` 抬头/看镜头呼应 + 注意力↑ |

- **安全阀（提案，强烈建议）**：全局快捷键（如 `Ctrl+Shift+H`，可配置）临时隐藏宠物 30 分钟或至再按，用于屏幕共享/会议/游戏。不改"默认置顶"决定，仅防社死。

## 11. 音频设计（节律随机环境声）

### 11.1 策略
- **环境声**：按昼夜节律随机偶发（白天频率较高、夜间安静），频率/音量可调。模拟"它在过自己的生活，偶尔出声"。
- **动作触发声**：讨食/玩耍/被抚摸等动作叠加对应采样。
- 音频与视频**分离入库**（一段视频可关联一个音频 id，也可静音播放）。
- **音画同步例外（v0.2 新增）**：`embeddedAudio: true` 的发声片段（§4.8）播放内嵌音轨以保证同步，不另叠加采样。

### 11.2 防噪音
- 同一声效**多采样**轮播；每次发声后设**冷却时间**与**单位时间上限**。
- 全局静音开关；默认音量偏低。
- 不干扰系统音频（仅自身播放，不做 ducking）。

## 13. 可靠性与边界情况

| 情况 | 处理 |
|---|---|
| 始终置顶遮挡（会议/游戏） | 安全阀快捷键临时隐藏（§10）；未来可加勿扰模式 |
| 缺关键状态片段 | 占位（端坐）+ 清单标红提醒补拍（§5.5） |
| 抠像质量差 | 预览拦截，引导调背景/光/重拍 |
| 长时闲置变体耗尽 | 回退最常见变体 + 拉长间隔（§9.5） |
| 崩溃 | 重启恢复 needs-state；FSM **重置回锚定态**重新调度（不恢复中段姿态，简单可靠） |
| 分辨率/显示器/任务栏变化 | 重新计算工作区、地面线与尺度（§7.1），宠物回到可见区 |
| 素材库为空 | 不渲染宠物，弹引导采集，绝不崩溃 |
| 宠物在屏幕外 | 行走片段到边自动转身；异常位置启动时校正回地面线 |

## 14. 性能预算（目标，v0.2 修订）

- **空闲 CPU**：≤ 3%（小尺寸片段软解 + 低频调度）。
- **内存**：< 250MB（Electron 基线 150–250MB + 单窗口；Phase 4 优化目标 200MB 内）。
- **解码**：仅解码当前单段；**VP9-alpha 无硬解可用，走软解**——靠归一化小尺寸（§7.4）与 30fps 控制开销；不预解码全部片段。
- **磁盘**：单 pet 项目估算数十～数百 MB（视片段数与码率）；提供码率/分辨率档位。
- **电池**：空闲时调度间隔拉长、呼吸振荡降频。

## 15. MVP 分阶段路线图（v0.2 修订：拆 Phase 1、补验收标准）

> 野心完整版按下列阶段渐进交付，每阶段都可独立运行、均有明确验收标准。

- **Phase 0｜渲染打通**：透明置顶窗口 + 单段 WebM-alpha 循环播放 + 全局快捷键隐藏 + **行走观感 spike**（用手工稳定化的一段行走素材 → 位移曲线驱动窗口平移，验证滑步可接受度，§7.2）。
  - *验收*：alpha 边缘无黑边/底色残留；记录目标机器软解 CPU 实测值；行走连续观看 1 分钟无明显滑步违和。
- **Phase 1a｜入库管线**：色键抠像 + 裁剪/标 loop + **行走跟踪裁切与位移曲线（含手动校正）** + 转码 + 清单引导导入/打标 UI（最小启动集置顶）。
  - *验收*：用最小启动集完成全流程入库；抠像预览边缘放大检查通过；位移曲线校正可用。
- **Phase 1b｜运行时闭环**：双锚定中转 FSM（仅基础生命状态）+ 底部行走/转身（位移曲线驱动）+ 尺度归一化 + 静音。**此时已是一只像样的桌面宠物。**
  - *验收*：仅凭 6 段最小启动集运行 10 分钟无硬切、无锚定位置跳动；缺素材状态占位 + 标红提醒生效。
- **Phase 2｜交互与生命感**：抚摸/点击/拖拽（含命中盒缓冲带）+ 需求模型 + 性格参数化 + 节律 + 调度微随机 + 多变体/稀有动作 + 全局呼吸 + 道具类片段（§8.4）。
  - *验收*：交互抢占响应 < 200ms；性格滑杆改变行为分布可感知；穿透/交互切换无漏触发。
- **Phase 3｜音频与养成**：节律环境声 + 喂食/玩具 UI + 动作触发声。
  - *验收*：声效冷却与单位时间上限生效；`embeddedAudio` 片段音画同步。
- **Phase 4｜打磨**：多宠物/备份导出/设置面板/性能调优/抠像质量提升。
  - *验收*：§14 全部指标达标（内存 ≤ 200MB）。

## 16. 开放问题与待验证假设（风险，v0.2 修订）

1. **色键鲁棒性**：特定毛色（纯白/纯黑）与背景对比度不足时抠像失败——需 Phase 0 实测，可能需推荐背景色或加 AI 辅助。
2. **VP9-alpha 软解开销**：alpha 通道无硬解可用（已按软解设计）——Phase 0 实测目标机器上归一化尺寸片段的软解 CPU 占用；超预算则提供分辨率/帧率降级档位。
3. **Electron 常驻占用**：用户对 ~200MB 内存的接受度——若敏感，Phase 4 评估迁 Tauri。
4. **行走滑步观感（新增，高优先）**：位移曲线理论上消除滑步，但跟踪误差、平移与落地脚相位错位仍可能"看着飘"——Phase 0 spike 重点验证；兜底手段：降低行走频率、缩短单次行走跨度、行走类微随机降速幅度收窄。
5. **锚定中转在快速交互下的观感**：频繁抚摸时反复回锚定是否违和——Phase 2 实测，可能加交互态直连快路径。
6. **采集完成度（新增，高优先）**：最小可用集仍需 ~15–20 段合规素材，存在采集疲劳弃坑风险——靠最小启动集（6 段）快速见效 + 清单进度可视化 + 占位兜底缓解；实施后需观察真实完成率。
7. **人体遮挡观感（新增）**：背景色袖套下"宠物对无形之手起反应"是否违和——Phase 2 实测；备选：场外引导替代直接抚摸镜头（§4.7）。
8. **穿透/交互切换抖动（新增）**：`setIgnoreMouseEvents` 往返切换的已知坑（切换瞬间不触发 mouseenter、forward 模式高频 mousemove 开销）——命中盒缓冲带缓解（§6.1），Phase 2 实测。
9. **不对称花纹双方向采集可行性**：能否拍到转身/双向行走——若不可，则该宠物限定单向活动范围。
10. **稀有动作/招牌的"偶发不重复感"**：素材量有限时长期运行仍可能被识破循环——靠补拍持续缓解（在世可补拍是最大优势）。

## 附录 B：术语表

- **视频精灵（Video Sprite）**：以真实视频片段为帧源、按需播放合成的 2D 角色。
- **锚定姿态（集合）**：所有非循环片段统一的中性起止姿态，用于掩盖切换；本项目采用端坐（主锚定）+ 站立（副锚定）双锚定（§4.2）。
- **色键**：按背景纯色生成透明 alpha 的抠像法。
- **签名/招牌动作**：该宠物独有、低频偶发的个性化片段。
- **跟踪裁切（稳定化）**：抠像后逐帧跟踪宠物并裁切为定宽片段，使宠物在画面内近似居中，屏幕位移交由窗口平移提供（§5.3、§7.2）。
- **位移曲线**：行走片段的逐帧 x 偏移序列（`*.track.json`），运行时驱动窗口平移，保证脚爪不滑步（§7.2）。
