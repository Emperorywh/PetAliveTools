# PetAliveTools 产品与技术规格

版本：直接视频片段路线
更新日期：2026-08-14
状态：当前实现基线

## 1. 产品定位

PetAliveTools 是一个使用用户自备视频片段的桌面宠物程序。用户导入的片段必须已经由外部专业工具制作完成，并达到可直接播放的状态。

程序负责：

- 管理宠物项目和动作片段；
- 根据行为状态选择一个已导入文件；
- 使用 Electron/Chromium 的原生 `<video>` 能力播放完整文件；
- 处理点击、抚摸、拖拽、需求、性格、音频、托盘和多宠物切换；
- 备份和恢复项目中的原始片段。

程序不负责视频制作，也不试图替代专业抠图或剪辑软件。

## 2. 不可违反的媒体边界

### 2.1 导入等于文件复制

视频导入的唯一媒体操作是把源文件逐字节复制到项目的 `clips/` 目录。允许改变目标文件名，以便记录动作、方向和变体编号；文件内容和容器格式必须保持不变。

导入过程中：

- 不打开视频画面；
- 不读取帧；
- 不读取时长、帧率、分辨率、颜色或编解码信息；
- 不改写源文件；
- 不删除源文件；
- 不产生任何派生视频。

### 2.2 永久排除的功能

当前产品不提供、也不保留下列实现：

- 背景色选择、参考帧选择、色键、绿幕/纯色抠像；
- 抠像预览、边缘检查、去色溢、羽化、形态学处理；
- 视频抽帧、Canvas 逐帧处理、逐像素分析；
- 裁剪、缩放归一化、稳定化、画面镜像；
- 自定义循环入点或出点；
- 宠物质心识别、行走跟踪、位移曲线和 `track.json`；
- 按 `video.currentTime` 或逐帧轨迹移动窗口；
- 播放速率调整或随机变速；
- FFmpeg、转码、重新编码、容器转换、alpha 转换；
- 从视频抽取音轨；
- `clips.meta.json`、视频处理参数 schema 和轨迹元数据；
- 自动删除或移入回收站的“源视频清理”流程。

若某个文件不能被当前 Electron 版本直接播放，程序必须明确拒绝或显示播放失败，不得转码兜底。

### 2.3 “直接播放”的定义

“直接播放”表示将项目中复制后的文件 URL 交给一个原生 `<video>` 元素。以下属于正常播放器控制，不属于视频处理：

- 装载文件；
- 播放和暂停；
- 非循环文件自然触发 `ended`；
- 重播同一文件时回到文件开头；
- 使用 `video.loop` 对完整文件循环；
- 调整播放器容器透明度完成片段间淡入淡出；
- 使用 `object-fit: contain` 把画面放入固定宠物窗口。

播放器不得采样画面，不得通过媒体时间驱动其他系统状态。

## 3. 用户素材责任

用户应在导入前通过外部工具完成所有必要制作，包括但不限于：

- 抠图或透明背景制作；
- 纯色背景保留；
- 裁剪、稳定、构图和尺寸；
- 音画同步；
- 编解码器与透明通道选择；
- 希望形成循环时，对完整文件首尾进行处理；
- 左右方向和道具画面的最终制作。

PetAliveTools 不评价这些制作结果，也不会自动修正素材。

## 4. 支持的直接导入格式

导入窗口允许以下扩展名：

- `.webm`
- `.mp4`
- `.m4v`
- `.mov`
- `.ogv`
- `.ogg`

扩展名只作为允许列表。实际能否播放取决于当前 Electron/Chromium、操作系统和文件内的真实编解码器。扩展名通过不代表内容一定可播放，程序也不会做内容探测。

`.avi`、`.mkv` 等未列出的格式直接拒绝，不提供格式转换入口。

## 5. 直接导入流程

用户流程固定为：

1. 打开或创建宠物项目；
2. 选择动作状态；
3. 对需要方向的动作选择 `left` 或 `right`；
4. 选择一个已经制作完成的视频文件；
5. 程序以排他创建方式复制文件；
6. 程序重新扫描 `clips/`，新片段立即进入行为调度。

不存在中间预览、参数调整、保存处理结果或转码进度页面。

### 5.1 项目内文件名

新导入片段使用：

```text
<state>__<direction>__<variant>.<ext>
```

示例：

```text
idle_sit__none__01.webm
walk__left__01.mov
walk__right__02.mp4
```

规则：

- `state` 必须来自动作清单；
- `direction` 为 `left`、`right` 或 `none`；
- `variant` 从 `01` 开始，在同动作、同方向下递增；
- `ext` 保留源文件的容器扩展名并转为小写；
- 目标存在时不得覆盖；
- 方向只用于选择文件，绝不触发画面镜像。

## 6. 项目结构

```text
<pet-project>/
  persona.json
  needs-state.json
  behavior-config.json
  clips/
    <state>__<direction>__<variant>.<ext>
  audio/
    <独立音频文件>
  audio.meta.json
```

项目中不再创建或要求：

```text
clips.meta.json
clips/*.track.json
```

### 6.1 运行时片段描述

程序启动或项目刷新时，只读取 `clips/` 的目录项名称，并在内存中推导：

- `id` 和 `fileName`；
- 动作 `state`；
- `direction` 和 `variant`；
- 动作清单中声明的类别、锚定和“整文件循环”标记；
- 默认交互命中盒；
- 保留内嵌音轨标记。

该描述不写回磁盘，也不包含视频时长、循环点、尺度、轨迹或处理参数。

## 7. 播放与调度

### 7.1 文件播放

- 调度器把 `fileName` 解析成项目媒体 URL；
- 渲染进程使用单个 `<video>` 元素播放；
- 不设置自定义播放速率；
- 不镜像、不旋转、不做色键、不叠加呼吸缩放或接触阴影；
- 视频画面只按 `contain` 方式放入固定透明窗口；
- 视频内嵌音轨保持在原文件内，不做抽取。

### 7.2 生命周期

- 非循环片段必须播放完整文件；
- 渲染端只在原生 `ended` 事件发生后通知调度器推进；
- 主进程不得根据预计时长或墙钟猜测非循环片段结束；
- 标记为循环的动作使用 `video.loop` 循环完整文件；
- 行为系统可在既定停留时间后切换到另一个动作文件，但不修改循环文件本身。

### 7.3 窗口位置

视频播放不会驱动桌面窗口位置。

窗口位置只会因以下非视频事件改变：

- 应用启动或显示器工作区变化时，将窗口约束到可见区域并贴近底部；
- 用户主动拖拽窗口；
- 用户松手后的窗口回位逻辑。

`walk` 和 `turn` 只是行为状态名。播放这些片段时，程序不会自动平移、转向或跟踪脚步。

## 8. 行为、交互与音频

本次媒体路线调整不删除桌面宠物的非视频功能：

- 行为 FSM 和动作状态选择；
- 片段变体洗牌、空闲时长抖动和稀有动作概率；
- 点击、抚摸、拖拽等交互抢占；
- 饥饿、口渴、精力、注意力等需求状态；
- 昼夜节律和性格权重；
- 多宠物项目、托盘、快捷键、开机自启；
- 独立音频文件播放、音量、冷却和频率限制；
- 项目 zip 备份和恢复。

随机化不得改变媒体播放速率、画面方向、画面尺度或窗口坐标。

## 9. 配置边界

新配置不再包含：

- `rateJitter`；
- `screenPercent`；
- `symmetrical`；
- 任何片段级视频处理字段。

显示器设置只决定窗口出现在哪个工作区，不参与视频分辨率或缩放计算。

## 10. 旧项目兼容

- 可识别常见旧文件名，例如 `walk_right_01.webm`；
- 旧 `clips.meta.json` 和 `*.track.json` 不再读取、不再校验，也不参与播放；
- 程序不会主动删除用户旧项目中的这些文件，以避免不可逆的数据损失；
- 新项目和新的导入流程不会创建这些文件；
- 无法从文件名推导动作的旧视频不会自动进入调度，用户应通过直接导入窗口重新关联动作。

## 11. 实现与交付约束

- 仓库不得包含 FFmpeg 可执行文件；
- npm 依赖不得包含 `ffmpeg-static` 或其他自动媒体转换依赖；
- 打包配置不得复制媒体处理二进制；
- 主进程不得注册转码、抽帧、保存轨迹或视频源清理 IPC；
- preload 不得暴露上述接口；
- 导入页面不得创建用于视频预览或帧处理的 `video`/`canvas`；
- 调度 IPC 不得传递轨迹、镜像、速率、循环点或窗口位移载荷。

## 12. 验收标准

以下条件必须同时成立：

1. 任意允许扩展名的测试字节文件可以完成导入，即实现没有依赖视频解码；
2. 源文件与项目目标文件的字节内容完全一致；
3. 重复导入生成递增变体，不覆盖既有文件；
4. 不支持的扩展名明确拒绝，且不尝试转码；
5. 新项目不存在 `clips.meta.json` 和 `*.track.json`；
6. 项目加载只扫描文件名；
7. 非循环视频只由 `ended` 推进；
8. 循环视频只做完整文件循环；
9. 播放视频期间不会因媒体时间自动移动窗口；
10. 项目备份恢复后，片段字节保持一致；
11. 类型检查、自动化测试和生产构建通过；
12. 源码、依赖和打包资源中不存在旧视频处理实现。
