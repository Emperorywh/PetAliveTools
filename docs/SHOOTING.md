# 外部素材准备说明

版本：直接视频片段路线
更新日期：2026-08-19

本文档只说明导入前应准备什么。PetAliveTools 不参与拍摄素材的抠图、剪辑、裁剪、稳定、循环制作或转码。

## 1. 导入前完成制作

请在你选择的专业软件中完成最终视频，包括：

- 背景或透明通道；
- 画面构图和裁剪；
- 起止姿态；
- 完整文件的循环首尾；
- 左右方向；
- 音画同步；
- 最终容器和编解码器。

导出的文件应当已经能够在目标机器上直接播放。PetAliveTools 不会检查画面质量，也不会修复素材。

## 2. 推荐动作文件

基础动作：

- 端坐 `idle_sit`；
- 站立 `stand`；
- 行走 `walk`，需要时分别准备左、右文件；
- 趴卧 `lie`；
- 睡眠 `sleep`；
- 理毛 `groom`；
- 转身 `turn`，需要时分别准备左、右文件；
- 姿态过渡 `transition`（导入时选择起点与终点姿态，见第 5 节）。

互动动作：

- 被抚摸 `petted`；
- 点击回应 `clicked`；
- 被呼唤 `called`（右键菜单或托盘"呼唤"触发）；
- 被拖拽 `dragged`。

情绪和需求动作：

- 讨食 `beg_food`（饥饿较高时自动出现，喂食也播放它）；
- 喝水 `drink`（与讨食同组随机出现）；
- 求玩 `want_play`（注意力较低时自动出现，给玩具也播放它）；
- 无聊 `bored`（愉悦较低时自动出现）；
- 开心 `happy`（愉悦很高时自动出现）；
- 烦躁 `annoyed`（拖着不开心的小家伙时出现）。

个性招牌动作（C 类）没有固定清单：在导入页输入动作名称（如 backflip），
文件以 `sig_<名称>` 记录，播放时走短淡入淡出，低频随机触发。

## 3. 完整文件循环

动作清单中标记为循环的片段会通过浏览器原生 `video.loop` 循环整个文件。程序没有循环入点或出点设置。

如果需要无缝循环，请在外部软件中把文件首尾处理好，再导入最终成片。

## 4. 建议段数与时长

程序不探测视频时长，也不会在导入时自动提醒。以下数值是行为调度的参考建议：技术上任何时长都能直接播放——非循环片段按原生播放结束推进，循环片段在约 8 秒后轮换到下一个动作。偏离建议只影响观感，不影响运行。

最小启动集为 6 个主体：端坐、站立、行走（左、右各一）、趴卧、睡眠，外加过渡段。其余动作全部可选，缺失的动作会被调度器静默跳过。

| 动作 | 建议段数 | 循环 | 建议单段时长 |
| --- | --- | --- | --- |
| 端坐 `idle_sit` | 2–3 | 否 | 5–10 秒，首尾姿态一致 |
| 站立 `stand` | 1 | 否 | 5–10 秒，首尾姿态一致 |
| 行走 `walk` | 2–4 | 否 | 3–6 秒 |
| 趴卧 `lie` | 2–3 | 是 | 8–15 秒，完整文件首尾无缝 |
| 睡眠 `sleep` | 1–2 | 是 | 8–15 秒，完整文件首尾无缝 |
| 理毛 `groom` | 1–2 | 是 | 8–15 秒，完整文件首尾无缝 |
| 转身 `turn` | 1–2 | 否 | 1–3 秒 |
| 姿态过渡 `transition` | 2–4 | 否 | 1–2 秒 |
| 互动动作（B 类） | 各 1–2 | 否 | 3–8 秒 |
| 情绪 / 需求动作（D 类） | 各 1–2 | 部分循环 | 循环项 8–15 秒；其余 3–8 秒 |

说明：

- 行走与转身的建议段数已包含左、右两个方向，每个方向至少 1 段。
- 时长依据：循环片段在一个动作中合计展示约 12–16 秒（约 8 秒轮换窗口 + 空闲期继续循环），因此建议 8–15 秒且首尾无缝；短于约 5 秒会出现肉眼可见的重复，更长会在中途被切走。
- 端坐与站立虽为非循环片段，但空闲保活会在播完后自动从头重播，首尾姿态一致可避免接缝突兀。
- 过渡片段用于锚定姿态之间的中转，越短越不易被察觉。

## 5. 左右方向与行走位移

方向只用于给文件建立动作映射。程序不会镜像画面。

如果宠物左右花纹、道具位置或动作不同，请分别制作并导入左、右片段。即使画面理论上可以镜像，也应在外部软件中完成并导出最终文件。

**行走会真的走**：播放行走片段期间，宠物窗口按固定速度（约 60 像素/秒）
朝片段方向水平移动，走到屏幕可见边缘停下。因此：

- 左、右行走文件都准备，宠物才会两个方向溜达；
- 转身片段（左/右）会翻转朝向，其后的行走方向与转身画面一致；
- 行走速度固定，与视频内容无关，拍摄行走片段时按此速度预估步幅观感。

## 6. 过渡片段的端点

过渡片段在导入时需要选择**起点姿态**与**终点姿态**（端坐/站立/趴卧/睡眠/理毛），
文件名形如 `transition_sit_to_stand__none__01.webm`。

建议优先覆盖这些端点对：

- `sit ↔ stand`（坐↔站起身）；
- `sit ↔ lie`、`sit ↔ sleep`、`sit ↔ groom`（进出三个循环姿态）。

缺失的端点对在姿态切换时以极短淡入淡出兜底，画面会有轻微跳变。
旧版程序导入的无端点过渡文件（`transition__none__01`）不再参与切换，
请按端点重新导入。

## 7. 内嵌声音

程序保留视频文件已有的内嵌音轨，不会抽取或重新编码。如果需要调整音量、降噪或同步，请在导入前完成。

独立环境声和动作声可以放入项目的 `audio/` 库；这与视频处理无关。

## 8. 可直接导入的扩展名

当前允许：

```text
.webm  .mp4  .m4v  .mov  .ogv  .ogg
```

是否能实际播放取决于 Electron/Chromium 和文件内的编解码器。程序不会把不兼容文件转换成另一种格式。

## 9. 导入步骤

1. 在托盘菜单中打开"导入片段"；
2. 打开或创建项目；
3. 找到动作（过渡动作选择起点/终点姿态，招牌动作输入名称）；
4. 选择方向；
5. 点击"选择并导入"；
6. 选择已经制作完成的文件。

程序随后只做文件复制。页面不会要求背景色、参考帧、抠像参数、裁剪区间、循环点或跟踪校正。

## 10. 导入前自检

- [ ] 文件已经是最终成片；
- [ ] 每个动作的段数与单段时长参考第 4 节建议；
- [ ] 文件在目标环境能直接播放；
- [ ] 背景或透明效果已完成；
- [ ] 构图和尺寸已完成；
- [ ] 循环片段的完整文件首尾已完成；
- [ ] 左右方向文件已分别准备；
- [ ] 过渡片段的起点/终点姿态已规划（见第 6 节）；
- [ ] 音轨已经完成；
- [ ] 保留了外部制作工程和原始素材，以便日后修改。
