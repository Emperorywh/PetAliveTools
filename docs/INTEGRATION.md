# 直接片段主链路集成说明

更新日期：2026-08-14
依据：[SPEC.md](SPEC.md)

旧的抠像、跟踪和转码集成报告已经失效。当前主链路如下：

```text
选择项目与动作
  → 选择已制作完成的视频
  → fs.copyFile 逐字节复制
  → 扫描 clips/ 文件名
  → 行为调度选择 fileName
  → petmedia:// 本地媒体 URL
  → 原生 <video> 完整文件播放
  → 非循环文件 ended
  → 调度器选择下一个文件
```

## 1. 导入边界

主进程的直接导入入口只做：

- 绝对路径和文件存在性检查；
- 扩展名允许列表检查；
- 动作状态检查；
- 计算不覆盖既有文件的变体编号；
- `fs.copyFile(..., COPYFILE_EXCL)`；
- 重新扫描 `clips/`。

主进程不调用媒体解析器或外部二进制。渲染端导入页不创建视频预览和画布。

## 2. 资产发现

项目加载器不读取 `clips.meta.json`。它枚举 `clips/`，从文件名推导最小运行时描述。

无法识别的文件被忽略。常见旧式文件名可兼容识别；旧轨迹和旧元数据不参与运行时。

## 3. 调度边界

调度命令只允许携带：

- 片段 ID；
- 项目内真实文件名生成的 URL；
- 是否对完整文件循环；
- 命中盒；
- 是否保留内嵌音轨。

禁止携带镜像、播放速率、循环点、轨迹、媒体时间或窗口位置参数。

## 4. 播放生命周期

- 非循环文件：等待原生 `ended`，不得按预计时长完成；
- 循环文件：只使用 `video.loop` 循环整个文件；
- 重播同一非循环文件：从文件开头开始；
- 行为淡入淡出只改变播放器容器透明度；
- 播放器不采样帧，不向主进程上报媒体时间。

## 5. 窗口边界

调度器不生成窗口位置命令。`walk` 与 `turn` 只是动作文件的状态名。

主窗口仍可因启动定位、显示器变化和用户拖拽而移动，这些路径均不依赖视频内容或播放时间。

## 6. 已移除的集成面

- FFmpeg 路径解析、进程启动和进度解析；
- 转码、音轨抽取和 VP9-alpha 输出；
- 背景参考、抠像预览和边缘放大；
- 视频抽帧、裁剪和循环点编辑；
- 行走追踪、校正和轨迹文件；
- 媒体时钟上报与窗口位移；
- 视频镜像、尺度归一化、呼吸缩放和接触阴影；
- 视频源清理 IPC；
- `clips.meta.json` 和 `track.json` schema。

## 7. 防回归证据

自动化测试使用任意无效媒体字节执行导入，并断言：

- 导入成功，证明实现不尝试解码；
- 源和目标字节相同；
- 原容器扩展名保留；
- 不创建片段元数据；
- 重复导入不覆盖；
- 不兼容扩展名不转码；
- 非循环调度只由显式完成事件推进；
- IPC 载荷不含任何视频处理或窗口运动字段；
- zip 备份恢复后媒体字节相同。
